# ТЗ: «Варин блокнот» — Android-игра, сцены 1–3

## Что делаем
Офлайн-игра для девочки 11 лет. Героиня Варя (5 класс) живёт обычной жизнью: дом, кот Тимоша, подруги. В каждой сцене игрок оформляет место действия (раскрашивает, выбирает предметы), смотрит «живую» сцену с репликами, выполняет маленькое задание и получает карточку знаний (экономика, химия, биология, жизнь) в «Варин блокнот».
Стиль: карандаш и цветные карандаши на бумаге. Спокойно, без рекламы, без сети.

## Что в папке
- `design/screens/` — макет 15 экранов (по 5 на сцену). Это образец внешнего вида, повторить близко.
- `scenes/scene_01..03.json`, `speakers.json` — сценарии сцен. **Весь текст и данные берём только отсюда**, в код не зашиваем.
- `art/*.png` — иллюстрации (черновые): `*_gray.png` — карандашный набросок, без суффикса — раскрашенный вариант; `varya.png`, `cat.png`.
- `art/source/` — генератор рисунков (`generate_art.html` + `pencil_engine.js`, открыть в браузере → ссылки «Скачать»). `demo_coloring.html` — образец анимации раскрашивания штрихами.
- Полный список 56 сцен (на будущее, сейчас не нужен): https://claude.ai/artifact/8E2LgbrGn4CP4q6SHTocrT

## Технологии
- Kotlin + Jetpack Compose, Android Studio (уже установлена). Никаких Flutter/движков/тяжёлых SDK.
- minSdk 26, только 64-bit (arm64-v8a), R8 + shrinkResources.
- Хранение прогресса: DataStore. Сеть — только для проверки обновлений (раздел «Автообновление»), без аналитики и рекламы.
- PNG из `art/` перевести в WebP (качество ~85) при добавлении в проект.
- Шрифты: Caveat (заголовки, реплики) и Nunito (текст), из `res/font`, оба с кириллицей.
- Пакет: `com.example.varinbloknot` (позже заменю на свой).
- Проект: `C:\Projects\VarinBloknot`.

## Как устроен движок сцены
Сцена = данные из JSON, проходится за 5 шагов: **Начало → Оформление → Живая сцена → Маленькое дело → Блокнот**.
- **Начало**: картинка `art.color`, теги, заголовок, `story`, кнопка «Начать».
- **Оформление**: сверху `art.gray` и подсказка `hint`; вкладки `tabs`, палитра `palette`, карточки `items` (цена, если есть); если `budget` не null — полоса бюджета (потрачено/осталось). Кнопка «Готово, оживить сцену» → картинка проявляется из серой в цветную штрихами (маска, как в `demo_coloring.html`), ~1,5 с.
- **Живая сцена**: «живая иллюстрация», не мультик. Реплики `dialog` по тапу, пузырь на картинке + строка с аватаром внизу. `camera`: `wide` — весь кадр, `zoom_*` — плавный наезд ×1.3 к нужной области (координаты областей задать в JSON, поле добавить). `idle` — лёгкие анимации покоя: «дыхание» (scale 1.00–1.01, 3 с), покачивание. На этапе 1 рисунок цельный, поэтому анимации — только для всего кадра (лёгкое дыхание) и пузырей.
- **Маленькое дело**: по `task.type`: `budget` (чекбоксы, сумма ≤ лимита, иначе подсказка), `sort` (перетаскивание в два столбца, проверка), `quiz` (варианты, верный подсвечивается, `explain`).
- **Блокнот**: карточка `card` в виде листа тетради в линейку (поле красной линией слева), кнопки «В блокнот» / «Следующая сцена».
- Верхняя панель на всех шагах: «Назад», «Сцена N · Шаг», 5 точек прогресса, кнопка блокнота.
- Цвета: бумага `#f6efe0`, текст `#3d2f27`, вторичный `#6b5a4c`, акцент `#9c3a60`, линии `#e2d5bd`. Кнопки высотой 52 dp, скругление 16 dp, цели касания ≥ 44 dp.

## Автообновление (через GitHub, без Google Play)
Два уровня — чтобы новые сцены приходили без переустановки, а новая версия программы ставилась в пару касаний.

**А. Обновление контента (тихо, без участия).**
- В репозитории папка `content/`: `manifest.json` (`{"contentVersion": 3, "files": [{"path": "scenes/scene_04.json", "sha256": "…"}, …]}`), `scenes/*.json`, `art/*.webp`.
- При запуске (не чаще раза в 6 ч, только по Wi-Fi или если файлы маленькие) приложение читает `manifest.json` по raw-ссылке GitHub. Если `contentVersion` больше локальной — скачивает изменённые файлы во внутреннюю память, проверяет sha256, затем атомарно переключается на новый набор.
- Встроенный в APK контент — запасной вариант: нет сети или ошибка — играем на нём. Прогресс игрока не трогаем.
- Поле `minAppVersion` в манифесте: если контенту нужна новая версия программы — не применять, ждать пункт Б.

**Б. Обновление самой программы (с подтверждением).**
- APK выкладывается в GitHub Releases, тег `vX.Y.Z`, в описании — короткий список изменений.
- Приложение проверяет `releases/latest` (GitHub API, без токена) при запуске, не чаще раза в сутки. Если версия новее — мягкое окно «Есть новая версия: … Обновить?» → скачать APK → системное окно установки (`REQUEST_INSTALL_PACKAGES`, FileProvider). Полностью бесшумная установка на Android без Google Play невозможна — одно касание «Установить» нужно всегда.
- Подпись: один постоянный release-ключ (`keystore` вне репозитория, пароль — в `local.properties`/переменных окружения, не в git). Без того же ключа обновление не установится — предупредить меня и показать, где сделать резервную копию.
- `versionCode` растёт с каждым релизом.

**Публикация (скрипт для меня).** `publish.ps1`: собирает release APK, увеличивает версию, создаёт GitHub Release через `gh` и загружает APK; отдельная команда — выложить только контент (обновить `content/manifest.json`, закоммитить, запушить). Репозиторий: публичный `varin-bloknot` в моём GitHub (спросить имя аккаунта).

## Этапы (после каждого — остановиться и показать мне)
1. **Каркас, сцена 1 и автообновление.** Проект, тема, шрифты, верхняя панель, все 5 шагов сцены 1 по макету, чтение `scene_01.json`, сохранение прогресса. Автообновление А и Б, release-ключ, `publish.ps1`. Проверка: выпустить v0.1.0, затем v0.1.1 с изменённым текстом — телефон должен предложить обновиться; выложить правку в `scene_01.json` через контент — она должна появиться без переустановки.
2. **Сцены 2 и 3 — только данными.** Добавить JSON, все 3 типа заданий, наезд камеры, проявление цвета штрихами, экран «Блокнот» со списком полученных карточек.
3. **Слои для анимации** (отдельно, после моего «да»): доработать `art/source`, чтобы каждый предмет и персонаж выгружался отдельным слоем (серый слой + маска). В приложении: раскраска выбранным цветом (BlendMode.Multiply поверх серого), хвост кота, тесто поднимается и т. п. по `idle`.

- Скриншоты каждого экрана: `adb exec-out screencap -p > shots\s1-intro.png` и т. д. Показать их мне здесь, в Claude Code, рядом с соответствующими файлами из `design/screens/`, и кратко написать, что отличается.

## Правила работы
- Только то, что в этапе. Без лишних библиотек, без больших загрузок; если что-то нужно скачать — спросить.
- Экономить токены: не открывать картинки без нужды, PNG макета смотреть только при сверке.
- Короткие пояснения простым языком: что сделано и зачем.
